# LogMyDailyTask 요구사항 정의서 (PRD)

2026-11-13 · John S Lee

## 1. 개요

LogMyDailyTask는 재택·원격 근무자가 정해진 간격마다 짧은 팝업에 하던 일을 적게 하고, 캘린더 미팅과 합쳐 일주일 단위 워크로그 표를 자동으로 만들어 주는 무료 개인용 앱이다. 계정이나 서버 없이 모든 데이터는 사용자의 기기에만 저장된다.

**해결하려는 문제:** 원격 근무자는 주간 보고서나 타임시트를 쓸 때 "그때 뭘 했지?"를 기억에 의존한다. 기록이 귀찮으면 빠지고, 미팅은 따로 캘린더를 뒤져야 한다.

**목표**

- 기록 1회에 5초 이내: 이전 항목을 선택하거나 한 줄만 입력
- 근무 시간 중 체크인 응답률 80% 이상
- 주간 워크로그를 버튼 한 번으로 표 형태로 보고 내보내기
- Windows, macOS, iOS, Android(Galaxy), 웹 브라우저에서 동작

**제품 원칙 (확정)**

- 개인용 앱으로 시작한다 (팀·관리자 기능 없음)
- 무료, 광고 없음, 회원가입 없음
- 데이터는 기기 로컬에 저장, 회사 서버로 전송하지 않음. 원하면 사용자 본인의 Google Sheet에 모든 기기 기록을 모음

## 2. 대상 사용자 및 사용 시나리오

주 사용자는 시간 단위 업무 보고가 필요한 재택·원격 근무자와 프리랜서다.

| 사용자 | 필요 | 주로 쓰는 기기 |
| --- | --- | --- |
| 재택 직장인 | 주간 업무 보고, 상사와 진행 상황 공유 | Windows / macOS + 휴대폰 |
| 프리랜서·컨설턴트 | 고객별 청구 시간 근거 | macOS / Windows |
| 현장·이동 근무자 | 이동 중에도 간단히 기록 | iOS / Android |
| 설치가 어려운 회사 PC 사용자 | 프로그램 설치 없이 기록 | 웹 브라우저 |

**대표 시나리오**

1. 오전 9시 근무 시작 → 앱이 자동으로 체크인 타이머 시작
2. 9:30 팝업: "지금 무슨 일을 하고 있나요?" → 최근 항목 "ServiceNow 알림 수정"을 탭 한 번으로 선택
3. 10:00–11:00 캘린더의 "주간 팀 미팅"은 팝업 없이 자동 기록
4. 금요일 오후 주간 표를 열어 빠진 칸을 채우고 PDF/Excel로 내보내기

## 3. 지원 플랫폼

1단계부터 웹을 포함한 5개 플랫폼을 지원하며, 각 기기는 자기 로컬 저장소에 기록하고 알림은 OS·브라우저 제약에 맞춘다.

| 플랫폼 | 최소 버전 (제안) | 체크인 표시 방식 | 로컬 저장소 | 비고 |
| --- | --- | --- | --- | --- |
| Windows | Windows 10 이상 | 화면 우하단 작은 입력 창 + 시스템 트레이 아이콘 | SQLite | 시작 시 자동 실행 옵션 |
| macOS | macOS 13 이상 | 메뉴바 아이콘 + 플로팅 입력 창 | SQLite | 알림 권한, 로그인 항목 등록 |
| iOS | iOS 16 이상 | 로컬 알림 → 알림에서 바로 입력(Quick Reply) 또는 앱 열기 | SQLite | 백그라운드 제약으로 예약 알림 방식 사용 |
| Android (Galaxy 포함) | Android 10 이상 | 알림 + 인라인 답장, 선택적으로 홈 위젯 | SQLite | 삼성 배터리 최적화 예외 안내 필요 |
| 웹 (PWA) | 최신 Chrome, Edge, Safari, Firefox | 브라우저 알림 + 탭 안 입력 창 | SQLite WASM (OPFS, 미지원 브라우저는 IndexedDB) | 탭 또는 설치한 PWA가 열려 있을 때만 알림, 브라우저 데이터 삭제 시 기록 손실 경고 |

참고: 요청서의 "매킨토시"와 "OS X"는 현재 macOS 하나로 본다.

## 4. 기능 요구사항 1 — 체크인 리마인더

사용자가 정한 간격마다 "지금 무슨 일을 하고 있나요?" 팝업이 뜨고, 응답은 직전 체크인 이후 구간(예: 9:30–10:00)의 기록이 된다.

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-1.1 | 간격 선택: 15분 / 30분 / 60분 (기본 30분) + 사용자 지정 간격(5–120분, 5분 단위) | 필수 |
| FR-1.2 | 근무 시간·요일 설정(예: 월–금 9:00–18:00), 이 범위 밖에서는 팝업 없음 | 필수 |
| FR-1.3 | 팝업 문구: "지금 하고 있는 일을 간단히 적어 주세요" + 입력창 + 최근/카테고리 선택 목록 | 필수 |
| FR-1.4 | 정각 기준 정렬(9:00, 9:30…) 또는 근무 시작 기준 중 선택 | 필수 |
| FR-1.5 | 다시 알림(5분 / 10분), 건너뛰기, "휴식 중" 버튼 | 필수 |
| FR-1.6 | 일시 정지: 30분 / 1시간 / 오늘 하루 | 필수 |
| FR-1.7 | 캘린더에 미팅이 있는 동안 팝업을 정지하고 그 구간을 미팅으로 자동 기록, 미팅이 끝나면 다음 간격부터 재개 (예외: FR-1.14) | 필수 |
| FR-1.8 | 응답 없이 지나간 구간은 "미기록"으로 남기고, 다음 팝업에서 "이전 구간도 같은 일?" 한 번에 채우기 | 필수 |
| FR-1.9 | 여러 기기에서 쓰는 경우 기기별로 알림 켜기/끄기 (기기 간 자동 닫힘은 동기화가 생기는 2단계) | 필수 |
| FR-1.10 | 컴퓨터 유휴 상태(예: 10분 이상 입력 없음) 감지 시 팝업 보류, 복귀 시 "자리 비움 동안 무엇을 했나요?" | 권장 |
| FR-1.11 | 방해 금지 모드·화면 공유·전체 화면 발표 중에는 알림을 조용히 표시 | 권장 |
| FR-1.12 | 단축키로 언제든 수동 기록 (예: Ctrl+Shift+L / Cmd+Shift+L) | 권장 |
| FR-1.13 | 보조 타이머: "지금부터 이 일" 시작/정지, 타이머가 도는 동안 체크인 팝업 생략, 정지하면 하나의 기록으로 저장 | 권장 |
| FR-1.14 | 옵션: 1시간 이상인 미팅 중에도 체크인 팝업 표시 (기본 꺼짐, 기준 시간은 설정에서 조정 가능). 켜면 미팅 기록은 그대로 두고, 체크인 답변은 그 미팅 안의 세부 기록으로 저장 — 긴 워크숍·교육·작업 세션용 | 권장 |

## 5. 기능 요구사항 2 — 작업 입력 및 카테고리

한 번이라도 적은 내용은 카테고리별로 저장되어, 다음부터는 목록에서 고르기만 하면 된다.

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-2.1 | 자유 입력(한 줄, 최대 200자) + 선택 메모 | 필수 |
| FR-2.2 | 자동완성: 첫 글자를 입력하는 순간부터 지난 7일 동안 기록한 작업(Activity)에서 일치 항목을 바로 제안. 순서는 앞부분 일치 → 포함 → 한글 초성 일치(예: "ㅁㄴ" → "매뉴얼"), 같은 조건이면 7일 내 사용 횟수가 많고 최근에 쓴 순. 제안마다 카테고리·프로젝트를 함께 보여 주고 선택하면 같이 채움. ↑↓·Enter·Tab으로 선택. 7일 안에 일치가 없으면 "이전 기록에서 찾기"로 전체 항목 검색 | 필수 |
| FR-2.3 | 팝업 상단에 "직전과 같은 일" 버튼 1개 + 최근 5개 항목 | 필수 |
| FR-2.4 | 카테고리별 그룹 목록(예: 개발 / 회의 / 지원 / 문서 / 행정) 에서 선택 | 필수 |
| FR-2.5 | 새 항목 저장 시 카테고리 지정 또는 새 카테고리 생성 | 필수 |
| FR-2.6 | 카테고리 관리: 이름 변경, 색상, 병합, 보관(숨김) | 필수 |
| FR-2.7 | 선택 필드: 태그 | 권장 |
| FR-2.8 | 자주 쓰는 항목 고정(즐겨찾기) | 권장 |
| FR-2.9 | 입력 문장을 보고 카테고리 자동 추천 (규칙 기반 → 이후 AI) | 2단계 |
| FR-2.10 | 한국어·영어 입력 모두 지원, 한글 IME 조합 중 Enter 오작동 방지 | 필수 |
| FR-2.11 | 프로젝트 관리: 이름, 고객, 색상, 상태(진행 중 / 피드백 대기 / 완료), 완료된 프로젝트는 선택 목록에서 숨김, 항목·기록에 프로젝트 연결(선택) | 필수 |
| FR-2.12 | 프로젝트별 시간당 단가와 통화(선택 입력), 프리랜서 청구 근거용 | 권장 |

**용어 정리:** "항목(Activity)"은 재사용되는 작업 이름, "기록(Entry)"은 특정 시간 구간에 항목을 붙인 것이다.

## 6. 기능 요구사항 3 — 캘린더 연동 (Outlook / Google)

사용자는 설정에서 Outlook(Microsoft 365) 또는 Google Calendar를 선택해 연결하고, 앱이 서버 없이 캘린더를 직접 읽어 수락한 미팅을 워크로그에 넣는다.

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-3.1 | 연결 선택: 없음 / Outlook / Google Calendar (둘 다 연결도 허용) | 필수 |
| FR-3.2 | 앱에서 직접 OAuth 2.0 (PKCE) 로그인, 읽기 전용 권한만 요청 (Microsoft Graph `Calendars.Read`, Google `calendar.readonly`) | 필수 |
| FR-3.3 | 미팅 기록 내용: 제목, 시작·종료 시간, 참석자 수, 온라인 여부(Teams/Meet/Zoom 링크), 장소 | 필수 |
| FR-3.4 | 기록 대상 필터: 수락한 미팅만 / 미정 포함 / 종일 일정 제외 / 개인 일정 제외 | 필수 |
| FR-3.5 | 미팅은 "회의" 카테고리로 자동 분류, 사용자가 수정 가능 | 필수 |
| FR-3.6 | 미팅이 끝난 뒤 짧은 메모 팝업: "이 미팅의 결과나 메모가 있나요?" (선택) | 권장 |
| FR-3.7 | 일정 변경·취소 반영: 앱 실행 중 15분마다, 그리고 각 체크인 직전에 변경분 조회 (Graph delta query / Google sync token) | 필수 |
| FR-3.8 | 미팅 설명(본문)은 기본적으로 저장하지 않음, 사용자가 켜면 저장 | 필수 |
| FR-3.9 | 미팅 중에는 체크인 팝업이 정지되므로(FR-1.7) 겹침이 생기지 않음(FR-1.14를 켠 긴 미팅에서는 미팅 칸 안에 체크인 내용을 세부 기록으로 함께 표시), 수동 기록이 겹치면 미팅을 우선 표시하고 수동 내용은 메모로 보존 | 필수 |
| FR-3.10 | 연결 해제 시 토큰 즉시 폐기, 이미 기록된 미팅 유지 또는 삭제 선택 | 필수 |
| FR-3.11 | 토큰은 OS 보안 저장소에 보관 (웹은 브라우저 세션 동안만 유지, 재로그인 필요) | 필수 |

**회사 Microsoft 365 관리자 동의 안내 (확정 방식)**

회사 계정은 IT 관리자가 외부 앱 승인을 막아 둔 경우가 많으므로, 앱이 아래 순서로 안내한다.

1. 로그인 시 "관리자 승인 필요" 오류를 감지하면 전용 안내 화면을 띄운다.
2. 안내 화면에서 IT 담당자에게 보낼 요청 메일 초안을 제공한다: 앱 이름, 요청 권한(`Calendars.Read`, 읽기 전용), 데이터가 기기 밖으로 나가지 않는다는 설명, 관리자 동의 링크.
3. Microsoft 365의 "관리자 승인 요청" 기능이 켜진 회사면 앱에서 바로 요청을 보낼 수 있다고 알려 준다.
4. 승인을 기다리는 동안 대안을 제시한다: Outlook에서 게시한 ICS 캘린더 링크를 붙여 넣어 읽기 (조직이 게시를 허용한 경우).
5. 둘 다 안 되면 캘린더 없이 체크인만으로 사용하고, 미팅은 수동 기록에서 "회의" 카테고리로 선택하게 한다.

Google Workspace도 같은 흐름을 쓰며, Google OAuth 앱 검수(민감 스코프)는 출시 전에 완료해야 한다.

## 7. 기능 요구사항 4 — 주간 워크로그 테이블

주간 화면은 행 = 시간 구간, 열 = 요일인 표로 체크인 기록과 미팅을 함께 보여 준다.

| 9:30–10:00 | [개발] API 연동 | [회의] 팀 스탠드업 | [개발] 테스트 | [문서] 매뉴얼 | [개발] 배포 |

| 합계 | 개발 4.5h · 회의 2h … | … | … | … | … |

**시트 구조 ("Log" 탭, 1행은 머리글)**

| 열 | 이름 | 예시 |
| --- | --- | --- |
| A | entry_id | 0193f2c1-… |
| B–D | 날짜 · 시작 · 종료 (현지 시간) | 2026-11-12 · 10:30 · 12:00 |
| E | 시간(분) | 90 |
| F–H | 카테고리 · 프로젝트 · 내용 | 개발 · Client A · API 연동 |
| I–K | 메모 · 출처 · 상태 | — · checkin · logged |
| L–M | 기기 이름 · 플랫폼 | John의 MacBook · macOS |
| N–O | 수정 시각(UTC) · 삭제됨 | 2026-11-12T18:02Z · FALSE |

사용자가 시트에서 행 순서를 바꾸거나 정렬해도 A열의 entry_id로 행을 다시 찾는다. 시트에서 직접 고친 값은 앱으로 되돌아오지 않으며(앱 → 시트 단방향, FR-6.9의 가져오기는 다른 기기 기록만 해당), 이 점을 설정 화면에 안내한다.

## 10. 데이터 모델

핵심 엔터티는 11개이며, 모든 레코드는 백업 병합을 위해 `updated_at`과 소프트 삭제(`deleted_at`)를 가진다.

| 엔터티 | 주요 필드 | 설명 |
| --- | --- | --- |
| Profile | id, name, timezone, locale | 기기 안의 사용자 정보 (계정 아님) |
| Settings | interval_min (15/30/60 또는 사용자 지정), work_days, work_start, work_end, pause_during_meetings, checkin_in_long_meetings, long_meeting_min (기본 60), auto_purge_months (없음 / 3 / 6), purged_before (마지막 삭제 기준일), idle_threshold_min | 체크인·근무 시간 설정 |
| Category | id, name, color, sort_order, archived | 업무 분류 |
| Project | id, name, client, color, status (active / awaiting_feedback / completed), hourly_rate (nullable), currency | 프로젝트·고객과 단가 (참고 프로젝트의 Project + Rate를 개인용으로 합침) |
| Activity | id, category_id, project_id (nullable), title, tags, last_used_at, use_count, pinned | 재사용되는 작업 항목 |
| Entry | id, activity_id (nullable), project_id (nullable), start_at (UTC), end_at (UTC, nullable = 진행 중 타이머), tz_name, note, source (checkin / manual / calendar / timer), status (logged / missed / break), parent_entry_id (nullable, 긴 미팅 안의 체크인), device_id, sheet_sync_state (none / pending / synced / failed), sheet_synced_at, sheet_error | 시간 구간 기록, 소요 시간·금액은 저장하지 않고 계산 |
| SavedFilter | id, name, kind (fixed / relative), date_from, date_to, amount, unit (day / week / month / year), category_id, project_id, source | 저장된 로그 필터 (참고 프로젝트의 Static / Relative 필터) |
| CalendarConnection | id, provider (outlook / google / ics), account_email, secure_storage_key, sync_cursor, filters | 캘린더 연결 정보 (토큰 자체는 OS 보안 저장소) |
| CalendarEvent | id, connection_id, external_id, title, start_at, end_at, attendee_count, online_link_type, response_status | 가져온 미팅 (Entry와 연결) |
| Device | id, name (사용자 변경 가능), platform (windows / macos / ios / android / web), is_this_device, last_seen_at | 기록을 저장한 기기 (시트에서 가져온 다른 기기 포함) |
| SheetConnection | id, account_email, spreadsheet_id, sheet_name, secure_storage_key, enabled, last_synced_at, last_error, import_others | Google Sheets 연결 정보 (토큰은 OS 보안 저장소) |

진행 중 타이머는 `end_at`이 비어 있는 Entry 하나로 표현하며, 동시에 하나만 허용한다. 금액은 `(end_at − start_at) × hourly_rate`로 표시할 때 계산한다.

주간 표는 Entry를 시간 구간별로 묶어 계산하며, 따로 저장하지 않는다.

## 11. 기술 아키텍처 제안

하나의 크로스플랫폼 코드베이스로 5개 플랫폼을 지원하고, 백엔드 서버 없이 모든 기록을 기기 로컬 DB에 저장한다. 캘린더는 앱이 사용자 토큰으로 직접 읽으므로 운영 서버 비용이 들지 않는다.

```
┌─────────────── LogMyDailyTask 앱 (단일 코드베이스, 서버 없음) ───────────────┐
│  Windows      macOS        iOS          Android        웹 (PWA)              │
│  트레이·팝업  메뉴바·팝업  로컬 알림    인라인 답장    브라우저 알림          │
│  ─────────────────────────────────────────────────────────────────────────  │
│  로컬 DB (SQLite · 웹은 SQLite WASM) · 기기 안에만 저장 · 오래된 기록 자동 정리 │
│  ─────────────────────────────────────────────────────────────────────────  │
│  체크인 스케줄러                    캘린더 클라이언트                        │
│  근무 시간·간격·미팅 중 정지        OAuth (PKCE)·주기적 변경 조회            │
└──────────────┬───────────────────────────────┬───────────────────────────────┘
               │ 백업 파일 내보내기·가져오기   │ 읽기 전용
               ▼                               ▼
   내 파일 · 내 클라우드 폴더         Microsoft Graph    Google Calendar API
   (자동 병합은 2단계)                (Outlook 일정)     (캘린더 읽기 · Sheets 기록)
```

| 계층 | 추천 | 대안 | 이유 |
| --- | --- | --- | --- |
| 앱 (5개 플랫폼) | Flutter (Windows·macOS·iOS·Android·Web 단일 코드) | React Native + Tauri, 또는 웹(PWA) + Tauri 래핑 | 한 사람이 5개 플랫폼 유지, 데스크톱 트레이·팝업 지원 |
| 로컬 저장 | drift + SQLite (데스크톱·모바일: SQLCipher 암호화 DB 파일 / 웹: SQLite WASM, 브라우저 OPFS에 저장) | Isar, Realm | 오프라인 기록, 주간 집계 쿼리 |
| 보안 저장 | Keychain, Windows Credential Manager, Android Keystore | — | OAuth 토큰·DB 암호화 키 보관 |
| 캘린더 | Microsoft Graph(MSAL), Google Calendar API, ICS 링크 | — | 읽기 전용, PKCE로 클라이언트에서 직접 인증 |
| 알림 | OS 로컬 알림, 브라우저 Notification API | — | 푸시 서버 불필요 |
| 내보내기 | 앱 안에서 xlsx·CSV·PDF 생성 | — | 데이터가 기기 밖으로 나가지 않음 |
| 웹 호스팅 | 정적 호스팅 (예: Cloudflare Pages) | GitHub Pages | 서버 코드 없음, 비용 거의 0 |
| 로그 모으기 | Google Sheets API (values.append / batchUpdate), drive.file 스코프 | — | 서버 없이 모든 기기 기록을 사용자 본인 시트 한 곳에 모음 |

1단계에는 Laravel 같은 API 서버가 필요 없다. 2단계 자동 동기화도 사용자 클라우드 폴더를 쓰면 서버 없이 유지할 수 있다.

## 12. 기존 유사 제품 및 차별화

시간 추적 앱은 많지만, "주기적으로 물어보는 방식 + 캘린더 미팅 자동 병합 + 주간 표"를 한 번에 가볍게 하는 제품은 드물다.

| 유형 | 예시 | 방식 | 이 앱과 다른 점 |
| --- | --- | --- | --- |
| 타이머형 | Toggl Track, Clockify | 사용자가 시작/정지 버튼을 누름 | 켜는 걸 잊으면 기록 누락 |
| 자동 추적형 | RescueTime, Timing(macOS) | 앱·웹 사용을 자동 수집 | "무슨 일"이 아니라 "어떤 앱"을 기록, 감시 느낌 |
| 무작위 핑형 | TagTime 계열 | 무작위 시각에 질문 | 정해진 간격·주간 보고 표가 없음 |

**차별화 포인트**

- 정해진 간격으로 짧게 묻는 방식이라 기록 누락이 적고 감시 도구가 아님
- 이전 항목 원탭 선택으로 입력 부담 최소화
- Outlook·Google 미팅을 자동으로 같은 표에 병합하고, 미팅 중에는 팝업이 멈춤
- 바로 제출할 수 있는 주간 표 + Excel/PDF 내보내기
- 완전 무료, 계정 없음, 데이터는 내 기기에만 저장

위 제품 기능은 작성 시점의 일반적 이해이며, 출시 전 최신 기능을 다시 확인해야 한다.

### 오픈소스 LogMyWork(holgus103)와 비교

이름이 비슷한 오픈소스 프로젝트 LogMyWork는 ASP.NET MVC로 만든 팀용 시간 추적 웹 앱이며, 프로젝트·단가·필터 아이디어를 개인용으로 줄여 가져오고 팀 권한·이슈 기능은 제외한다. ([GitHub 저장소](https://github.com/holgus103/LogMyWork), 마지막 커밋 2022년 2월)

| 항목 | holgus103/LogMyWork | 이 문서의 LogMyDailyTask | 반영 |
| --- | --- | --- | --- |
| 형태 | 서버 DB 기반 웹 앱, 오픈소스 | 5개 플랫폼 로컬 앱 | — |
| 기록 방식 | 시작/정지 실시간 타이머 | 주기적 체크인 팝업 | 보조 타이머 추가 (FR-1.13) |
| 프로젝트 | 프로젝트 생성·수정, 상태(진행 중 / 피드백 대기 / 완료) | Activity의 텍스트 필드 | Project 엔터티 + 상태 추가 (FR-2.11) |
| 시간당 단가 | 프로젝트별 사용자 단가, 기록마다 금액 계산 | 없음 | 프로젝트 단가·금액 열 추가 (FR-2.12, FR-4.11) |
| 로그 필터 | 기간·프로젝트·작업·사용자 필터, 고정/상대 기간 필터 저장 | 주 단위 이동만 | 필터 + 저장된 필터 (FR-4.12, FR-4.13) |
| 시간대 | 모든 기록에 시간대 조정 | 프로필 시간대 하나 | 기록마다 UTC + 시간대 저장 |
| 역할·권한 | Owner / Manager / Worker / Client | 개인용 | 제외 |
| 작업 배정·마감일, 이슈, 첨부 파일 | 있음 | 없음 | 제외 (워크로그 범위 밖) |
| 캘린더 연동·리마인더 | 없음 | 핵심 기능 | — |

**DB 구조에서 참고한 점:** 기록(`TimeEntry`)은 종료 시각을 비워 두는 방식으로 진행 중 타이머를 표현하고, 소요 시간과 금액은 저장하지 않고 단가 × 시간으로 계산한다. 필터는 고정 기간(From/To)과 상대 기간(최근 N일·주·월·년) 두 종류로 저장한다.

## 13. 릴리스 범위 및 성공 지표

MVP는 웹을 포함한 5개 플랫폼에서 체크인·카테고리·캘린더 연동·주간 표·내보내기·백업까지를 무료 개인용으로 출시하는 것이 목표다.

| 단계 | 포함 범위 |
| --- | --- |
| MVP (1단계) | Windows·macOS·iOS·Android·웹, FR-1 체크인(사용자 지정 간격, 미팅 중 정지, 보조 타이머), FR-2 입력·카테고리·프로젝트(상태, 단가), FR-3 Outlook + Google + ICS 읽기 연동과 관리자 동의 안내, FR-4 주간 표 + 필터 + 금액 열 + Excel/CSV 내보내기, FR-5 로컬 저장·백업, FR-6 Google Sheets 동기화·모바일 CSV 내보내기, 한/영 UI |
| 2단계 | 사용자 클라우드 폴더를 통한 기기 간 자동 병합, 기기 간 알림 자동 닫힘, 유휴 감지, PDF 내보내기, 저장된 필터, 미팅 후 메모 팝업 |
| 3단계 | 기기 안에서 동작하는 카테고리 추천·주간 요약, 타임시트 양식 내보내기 템플릿 |

팀·관리자 기능과 유료 플랜은 범위에서 제외한다.

**성공 지표 (출시 후 3개월)**

- 근무 시간 중 체크인 응답률 80% 이상
- 기록 1건 평균 소요 시간 5초 이하
- 이전 항목 선택 비율 60% 이상 (새로 타이핑하지 않음)
- 앱 스토어 평점 4.5 이상, 누적 설치 수

서버가 없으므로 앞의 세 지표는 사용자가 켠 익명 통계로만 측정한다.
